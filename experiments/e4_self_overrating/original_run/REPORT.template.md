# Is a quality metric still trustworthy once 3DGS is trained on it?

Objective evaluation of 3D Gaussian Splatting models fine-tuned with nine image-quality metrics as
losses, on eight scenes. This file is generated by `scripts/build_report.py` from
`REPORT.template.md`; every result number is read from `results/tables/`, which
`scripts/analyse.py` derives from the long table `results/metrics.csv` (section 11 lists the few
numbers that come from other files). No subjective experiment was run; the stimuli for one are in
`stimuli/`.

## 1. Summary

**What was done.** For each of {{ len(CFG("scenes")) }} scenes a 3DGS model was trained with the default loss
({{ CFG("stage_a_steps") }} steps, standard densification). From that checkpoint, with the set of Gaussians
frozen, the model was fine-tuned for {{ CFG("stage_b_steps") }} steps with the default loss again (`ctrl`), with
each of {{ len(CFG("pure")) }} metrics alone as the loss ("pure") and with the default loss plus
{{ len(CFG("mixed")) }} of them ("mixed"). Every model was scored with {{ len(M.IMAGE_METRICS) }} image metrics on
held-out and on training views and, on the four scenes that have a reference video, with ColorVideoVDP
in video mode. One scene (truck) was run with three seeds. All improvements are measured against
`ctrl`.

**Runs.** {{ RS("n_done") }} of {{ RS("n_runs") }} runs finished, {{ RS("n_failed") }} failed,
{{ RS("n_not_ok") }} diverged (non-finite loss or gradient), {{ RS("n_incomplete") }} stopped early; the
number of Gaussians differs from the baseline in {{ RS("n_gaussians_changed") }} runs.

data cannot decide which metric is right. The most informative comparisons are `ctrl` against the mixed
and pure LPIPS-VGG, LPIPS-Alex and DISTS models and against pure ColorVideoVDP.

## 2. Question, and how it connects to the existing project

The existing project asked which metric to use for novel view synthesis and compared metrics on models
that were degraded on purpose (fewer views, iterations or Gaussians) and against subjective scores of
different methods. This experiment adds the case in which the difference between two models is caused by
the metric itself. Both parts answer one question:

> **When does a higher metric score mean a better rendering in novel view synthesis?**

The answer depends on what makes the two renderings differ, and the same three checks apply in each case:

| what makes the models differ | do metrics agree with each other? | do they agree with observers? | video vs per-frame metrics |
|:--|:--|:--|:--|
| amount of degradation (ladders) | existing report, Part 1; section 6.6 here | pairwise experiment planned (pilot only) | existing report (flicker probe) |
| kind of artefact: methods, scenes | existing report, Parts 1-2; section 6.6 | existing report, Part 2 (GS-QA, NVS-QA) | existing report, Part 2 |
| training objective (this experiment) | sections 6.1-6.3, 6.6 | **not done**: stimuli exported (section 8) | section 6.5 |

Three hypotheses were tested; each could fail:

1. A model trained with metric M as its loss is overrated by M, relative to independent metrics.
2. Evaluating with another metric of the same family does not remove this.
3. A loss acts only on training views; perceptual losses may paint detail there that becomes an artefact
   in novel views and in motion, visible to video metrics but not to per-frame metrics.

## 4. What was run

**Scenes.** The eight scenes of Part 1 of the existing project: truck, train, playground2, flowers (GS-QA:
the training video is the training set, the frames of the separate reference video are the test views, cropped
to 928x522) and kitchen, bonsai, garden, bicycle (Mip-NeRF 360).

**Stage B.** Starting from the stage-A checkpoint: no densification, pruning or opacity reset (no gsplat
strategy is called), spherical-harmonics degree 3, {{ CFG("stage_b_steps") }} steps, one training view per step
in a seeded random order. Learning rates are those the baseline ended with (positions: 0.01 x the initial
rate, the end of the exponential schedule; all other groups are constant in 3DGS). Adam starts with empty
moments because the baseline's optimiser state is not part of the checkpoint; this is the same for every
condition including `ctrl`.

**Conditions** ({{ len(META("conditions")) + 1 }} models per scene and seed):

| name | loss |
|:--|:--|
| base | the stage-A model, not fine-tuned (reference row only) |
| ctrl | default loss, 0.8 L1 + 0.2 (1 - SSIM), SSIM as in stage A (zero padding) |
| pure | L1; L2 (MSE); D-SSIM = 1 - SSIM; 1 - MS-SSIM; LPIPS-VGG; LPIPS-Alex; DISTS; FLIP (mean error); ColorVideoVDP (10 - JOD) |

## 6. Results

Definitions (fixed before the full results were seen; code in `scripts/analyse.py`):

* **Improvement over ctrl**, per view: value(model) - value(ctrl), sign-flipped where smaller is better, so
  that positive always means better than `ctrl`.
* **z**: the improvement divided by s_m, the standard deviation of the per-scene mean improvement of metric
  m over all 16 trained models and 8 scenes (held-out views). s_m is {{ f(SN("psnr", "scale"), 2) }} dB for PSNR,
  {{ f(SN("ssim", "scale"), 3) }} for SSIM, {{ f(SN("lpips_alex", "scale"), 3) }} for LPIPS-Alex,
  {{ f(SN("dists", "scale"), 3) }} for DISTS and {{ f(SN("cvvdp_image", "scale"), 2) }} JOD for ColorVideoVDP; the same
  s_m is used for training views.
* **Families**: {L1, MSE, PSNR}, {SSIM, MS-SSIM}, {LPIPS-VGG, LPIPS-Alex}; every other metric is its own
  family.
* **Confidence intervals**: 95 % percentile bootstrap, {{ META("bootstrap") }} replicates, resampling scenes and
  views within scenes, the same draws for all models and metrics.
* **Seed noise**: SD over the three truck seeds of the same statistic computed on truck. **An effect counts
  as a finding only if its interval excludes zero and it is larger than twice the seed SD** (marked * in
  tables and figures). The seed SD of one scene is compared with a mean over eight scenes, which is
  conservative.

## 9. Is a subjective experiment worthwhile?

Yes. The objective data establish that the metrics contradict each other about these models, by margins far
above seed noise and with visible differences, and they cannot say which side is right:

{{ tab_votes() }}

Suggested focus, in line with the pairwise-comparison plan of the existing project
(`../subjective_experiment_plan.md`):

* **`ctrl` against mixed LPIPS-VGG, mixed LPIPS-Alex and mixed DISTS.** These are the realistic cases (a
  perceptual term added to the standard loss). For the two LPIPS models the deep-feature metrics and DreamSim
  report an improvement and the pixel and structural metrics a small loss; the DISTS model is rated better by
  DISTS alone. PSNR changes by {{ fs(X("lpips_vgg/mixed", "psnr", "delta")) }},
  {{ fs(X("lpips_alex/mixed", "psnr", "delta")) }} and {{ fs(X("dists/mixed", "psnr", "delta")) }} dB.
* **`ctrl` against pure LPIPS-VGG, LPIPS-Alex and DISTS.** The largest sign conflicts.
* **`ctrl` against pure ColorVideoVDP.** The metric built on a model of contrast sensitivity rates this model
  as better; all {{ n_worse("cvvdp/pure") }} other metrics rate it as worse, and it has a colour cast.
* Mixed FLIP, mixed MS-SSIM, mixed ColorVideoVDP and mixed L2 differ from `ctrl` by little in every metric
  and are unlikely to be distinguishable; one of them can serve as a check.

With seven comparisons against `ctrl` on eight scenes this is 56 pairs per observer, close to the size the
existing plan foresees. For the GS-QA scenes the stimuli are videos; for the Mip-NeRF 360 scenes only still
images exist, so the question of artefacts in motion can be put to observers on four scenes only.

## 10. Limitations

* "Overrating" is defined against other metrics, not against people.
* Fine-tuning a converged model for {{ CFG("stage_b_steps") }} steps with a frozen set of Gaussians isolates the
  loss, but it is not how a method that trains with a perceptual loss from the start behaves; densification
  would react to the loss.
* One weight per mixed loss (equal means on the baseline); the dependence on the weight was not measured.
* Eight scenes, four of them with video; one seed for seven scenes. Intervals over four scenes are coarse.
* Seed noise was measured on truck, whose baseline is the most reproducible of the eight (section 3). The
  improvements over `ctrl` share a checkpoint and should be less affected than absolute values, but this was
  not verified on a scene with floaters; the bootstrap over scenes and views is the more important guard.
* The column scale s_m depends on the set of conditions; pure DISTS and pure ColorVideoVDP, the largest
  effects, set much of it.
* The natural-degradation side of section 6.6 comes from the existing project; for the GS-QA scenes its
  metrics were computed on decoded video frames, ours on the RGB renders.
* The bicycle baseline is {{ f(PUB("gsplat_docs_gsplat30k", "mip360/bicycle") - BV("mip360/bicycle", "psnr"), 2) }} dB below
  the published value for an unknown reason (section 3).
* DreamSim, FSIM and VIF were never losses, but each resembles one of the families.
